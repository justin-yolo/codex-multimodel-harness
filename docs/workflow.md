# 워크플로

## 의도한 운영 방식

이 하네스는 외부 모델 협업을 쓰되, 레포가 특정 머신 전용 셋업으로 굳어지지
않게 만들고 싶은 Codex 사용자를 위한 구조입니다.

## 기본 순서

1. Codex가 로컬 컨텍스트를 읽고 근거를 수집합니다.
2. Codex가 작업이 사소한지 아닌지 구분합니다.
3. 사소하지 않은 작업이면:
   - Gemini가 먼저 비판적으로 읽습니다.
   - 작업 중요도가 충분히 높으면 Claude가 리드 리뷰를 합니다.
4. Codex가 결과를 종합하고 실제 수정 또는 판단을 수행합니다.

## Gemini만 먼저 써도 되는 경우

- 작은 설계 질문
- 설정 리뷰
- 빠른 리스크 스캔
- 2차 의견만으로 충분한 단순 비판 검토

## Claude까지 올려야 하는 경우

- 설계 방향 변경
- 복잡한 디버깅
- 고위험 판단
- 최종 추천 품질이 특히 중요함
- Gemini와 로컬 근거가 의미 있게 충돌함

## Codex의 역할

Codex는 여전히 파일 수정, 명령 실행, 결과 검증, 사용자 보고를 담당하는
실행 런타임입니다. Claude와 Gemini는 실행 엔진이 아니라 리뷰 레이어입니다.
